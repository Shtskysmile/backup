## 二、逐项演示步骤与"标准答案"

### 1. 简单样本 → 基础分（备份/还原）
1. Backup 页：源=demo-small，目标=backup-out，名称 DemoSmall → Back up now。
2. 还原到 restore-out → 打开 readme.txt 内容一致。
**口径**：清单里 3 个条目，SHA-256 校验在还原时执行。

### 2. 复杂样本 → 筛选 + 增量
1. 展开筛选：Include paths 填 `实验数据/**`，Extensions 填 `log;dat` → 备份，展示归档里只有命中条目（中文路径正常）。
2. 不改文件再备一次 → 增量 0 条目（`archived 0 entries`）；改一个 measurement-*.dat 再备 → 增量仅 1 条目 + 目录。
3. Owners 填当前用户名 → 全保留；填 `no-such-user` → 空清单（属主筛选）。

### 3. 特殊文件 → 老师点名的"处理结果"
| 演示 | 还原后验证命令（现场跑） | 预期结果 |
| --- | --- | --- |
| 硬链接 | `fsutil hardlink list b-link.txt`（Win）/ `ls -li`（Mac） | 两个名字同一文件 ID / 同 inode |
| 软链接（文件） | `dir`（Win 显示 `<SYMLINK>`）/ `ls -l` | 目标仍是 report-body.txt |
| 断链 | 还原后 `type s-broken.lnk` 报找不到，但链接本身存在 | 断链原样保留，不报错不落数据 |
| FIFO 管道 | `ls -l`（Mac/Linux） | `prw-r--r--` 管道类型；备份过程不阻塞 |
| 设备/socket | 清单 `*.manifest.properties` 中 `type=CHARACTER_DEVICE`/`SOCKET` | 有记录；无特权时还原给警告、其余照常 |
| **Windows 降级** | 还原 demo-special 后 `dir` | 硬链接存为普通文件+日志警告——如实说明是公开 API 限制，POSIX 实跑通过 |

### 4. GB 级 → 健壮性与性能
1. 提前用 demo-big 跑一次 ZIP 和一次 GZIP，**记下耗时**（2GB 预计 10~40 秒/次，以实机为准）。
2. 现场讲三点：固定 64KB 缓冲（内存不随体积涨）、SHA-256 边写边算、压缩率对比（随机文件几乎不压缩 vs 日志文本压缩明显）。
3. 演示加密：勾选加密 + 口令备份 demo-big 一部分；错误口令还原 → 明确失败无输出文件。

### 5. 网络模式（如组内决定保留，约 2 分钟，零成本）
1. Network 页选空存储目录 → Start server（首次自动生成证书）→ Add user。
2. 客户端 localhost + 账号 → Test connection → 加密备份 demo-small → 改一个文件再备（增量）→ List snapshots 出 full+incremental。
3. Restore selected 到空目录，内容一致。
**口径**：不需要租服务器——接收端内置于软件，单机 localhost 或两台电脑同一 WiFi 即可；12 项网络自动化测试在 CI-less 环境全部通过。

### 6. 自动化（收尾，30 秒）
Schedule minutes=1 → Start schedule → 等一次自动触发日志；Watch debounce=5 → 改文件 → 实时备份触发。

## 四、常见追问口径

- "增量怎么判定？" → 类型+尺寸+SHA-256+修改时间+链接目标+权限/属主联合比较，目录恒随附。
- "删掉的文件还原会消失吗？" → 不会，增量只覆盖/新增，不同步删除（安全语义）。
- "加密怎么做的？" → AES-256-GCM 认证加密 + PBKDF2（21 万次迭代）派生密钥，错误口令无法解密。
- "网络要服务器吗？" → 不用租，接收端内置，localhost/局域网即可。
- "Windows 下硬链接为什么变普通文件？" → 公开 JDK API 在 Windows 不提供文件身份（fileKey=null），降级并警告；POSIX 实跑通过。
