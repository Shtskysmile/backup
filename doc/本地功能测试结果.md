## 已知边界

- 本轮验证环境为 macOS；未据此声明 Windows/Linux 均已实机验证。
- 软链接自身属性先检查，一致不告警；POSIX 属主/组按不跟随方式恢复，macOS 不同链接权限通过 chmod -h 恢复并核对。真正不支持或失败时报告警告，目标数据和属性必须保持不变。
- 属主、组及创建时间受文件系统和当前用户权限限制；失败时报告属性警告，不请求提权。
- 不支持命名设备文件和 socket 文件；跳过并提示。FIFO 在 POSIX 环境有条件支持，详见下文。
- 增量还原需用户依次选择全量及增量，不自动串联，不同步删除。前次恢复的只读目录可能需要用户调整权限后再叠加下一份增量。
- 保留单位是一组全量及其增量，默认 0 关闭淘汰。历史无索引或无法确认身份的备份不会被自动删除。

## 2026-11-05：本地 FIFO 修复与测试适配

未引入对方 v3 的网络包、设备重建或 socket 支持；编译目标继续 Java 21。

- 属主规则：3 个规则用例和 2 个真实扫描用例，覆盖与其他条件组合、未知属主、任务身份及祖先目录保留。
- 新增 `com.backup.io.SpecialFileTypeTest`：12 个测试，含 ZIP/GZIP/加密归档的 FIFO 全量与增量往返、权限变更、零尺寸筛选、非法载荷、错误基线、工具不存在/退出失败/伪成功、时间工具缺失、非空目录保护，以及未归档 FIFO 的目标权限漂移。
- FIFO 往返在独立 JVM 执行并设置进程截止时间，避免 native open 卡死整个 Surefire。临时恢复旧的阻塞权限调用后，测试确实以“FIFO restore hung in native attribute code”失败，且子进程被终止；恢复修复后通过。
- FIFO 权限由 `mkfifo -m` 设置，恢复时先暂存再替换；未变增量发现目标 FIFO 权限不同，也走安全重建。权限和时间恢复均不会通过 Java 的文件打开型属性接口访问管道。
- 修改/访问时间通过有 5 秒超时的 `touch -c -h` 尝试恢复，仅保证整秒精度；丢失毫秒精度及无法恢复创建时间均报告警告。
- Windows/其他文件系统对不支持的 POSIX、软硬链接、fileKey 和 FIFO 能力按用例假设跳过；普通功能测试、缺工具保留原文件等可移植失败路径继续执行。本次没有 Windows 实机运行，不虚报 Windows 通过数或跳过数。

完整 Maven `clean package`：81 项，失败 0、错误 0、跳过 0；本机 macOS / OpenJDK 26.0.2.1，编译目标 Java 21。

## 2026-11-05：软链接属性核验与安全恢复

用户截图中的四条“symbolic-link owner/group/permissions skipped to protect its target”来自无条件跳过逻辑。复查截图对应的真实 12 项 ZIP 归档：四个链接的实际 owner、group、mode 本来均与清单一致，因此此前警告具有误导性。

新增 `SymbolicLinkMetadataTest` 六项用例，前四项先在原实现上全部失败，再修复通过：

- 已匹配的相对、绝对、目录和断开软链接不产生虚假跳过警告。
- macOS 非默认链接权限正确恢复，外部文件的权限、mtime、atime 及内容不变。
- 非默认断开链接权限正确恢复，不创建缺失目标。
- 目录软链接权限恢复不修改目标目录的权限和时间。
- 不存在的属主名称保留明确的 owner 失败警告，不伪装成功。
- 模拟 chmod 返回 17 时保留具体失败原因及目标不变断言。

修复后用新版 JAR 再次把用户归档还原到独立临时目录：12 项还原完成，警告从 4 变为 0，四个链接的属主、组和权限逐项吻合。不会通过普通 JDK 权限设置器修改链接目标。macOS `clean package`：87 项，失败 0、错误 0、跳过 0；保持 Java 21 字节码。

这不等于所有权限操作都保证成功：改成任意其他用户可能需要系统权限，其他平台不支持可变链接权限时仍需报告真实限制。
