## 使用规则

- 讲稿是草稿，不要照着页面逐字读。
- 第 6 页含【待补】句：真实分工补齐之前不得照读，补齐后重新计时试讲。分工表里的“负责内容”是按 Git 提交推断的，须由本人确认。
- 第 5 页甘特图：前三行（需求分析、系统设计、核心实现）没有可核实的日期，保持“日期待补”；其余日期取自 Git 提交时间，其中 11-02 是导入既有实现的整理提交，不能说成当天写完。图上各里程碑的项数（64、87、102）是当时的测试数；讲稿说的 104 是现在的总数。
- 第 3 页的 Git 数字（25 次提交、两位作者、4 条功能分支）取自 2026-11-08 的核对；汇报前用 `git rev-list --count HEAD` 与 `git log --format=%an | sort | uniq -c` 再核一次。把本次界面修复提交之后，提交数会变，要重新数。
- 第 4 页的 104 来自 `mvn clean test` 的 surefire 结果（macOS，失败 0、错误 0、跳过 0；其中 2 项界面测试需要显示器，无显示器时按能力跳过）；整条演示流程的 GUI 层演练单列，不计入 104。
- 说“只用 JDK 标准库”时，如被追问补一句：FIFO / 设备恢复另调系统命令（mkfifo、touch、mknod），TLS 证书由 JDK 自带的 keytool 生成；不要说成“完全没有外部依赖”。
- 第 6 页最后一句是转入演示的信号，讲完立即切到软件，按《最短演示方案》操作。
