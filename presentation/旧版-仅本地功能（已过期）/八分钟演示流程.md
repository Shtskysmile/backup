# 八分钟演示流程

配套材料：`本地备份软件答辩.pptx` 第 6 页结尾转入演示；常见追问的回答口径见第 7 节。

**硬性限制：演示 8 分钟，严禁超时。** 本流程按 7 分 30 秒安排，留 30 秒回答问题；到 8:00 必须停止，不再补展示。

检查要求中的演示形式：老师 / 助教在同学的指导下**亲手**操作软件，完成数据备份与还原；同学提前准备能体现各项功能的待备份数据；过程中回答老师 / 助教的问题。

事实核对日期：2026-11-06（87 项测试，macOS）。相比 2026-11-02 的版本，本流程新增了**属主筛选**和 **FIFO 管道**两个演示点，并更新了软链接属性的预期现象。时间安排没有变：新增内容都嵌在原有环节里。

> 本文只描述操作，不替你执行：不会启动定时 / 监视任务，也不会清理任何现有备份。所有备份、还原和保留清理只在下面新建的演示临时目录里进行。

## 1. 课前准备

### 1.1 准备演示数据（新建临时目录）

仓库里已有小样本 `testfilefolder/link-demo/`（普通文件、两份硬链接，以及相对 / 绝对 / 目录 / 断开四种软链接），预期行为见该目录的 `说明.md`。

**正式演示建议另建临时目录**，避免覆盖或清理真实资料；不要复用 `encrypted/`、`decrypted/` 等已有目录。下面的命令只在新建目录里准备数据：

```bash
PPT_DEMO_ROOT="$(mktemp -d "${TMPDIR:-/tmp}/backup-ppt-demo.XXXXXX")"
export PPT_DEMO_ROOT
python3 - <<'PY'
import os
from pathlib import Path
r = Path(os.environ['PPT_DEMO_ROOT'])
s = r / 'source'
(s / 'docs').mkdir(parents=True)
(s / 'cache').mkdir()
(s / 'empty').mkdir()
(s / 'docs' / 'report.txt').write_text('备份演示：第一版。\n', encoding='utf-8')
(s / 'docs' / 'notes.log').write_text('日志样本\n', encoding='utf-8')
(s / 'README').write_text('无扩展名样本\n', encoding='utf-8')
(s / 'cache' / 'temp.txt').write_text('应被排除\n', encoding='utf-8')
(s / 'compress-sample.txt').write_bytes(b'backup-compression-demo\n' * 50000)
os.link(s / 'docs' / 'report.txt', s / 'docs' / 'report-hard.txt')
(s / 'relative-link.txt').symlink_to('docs/report.txt')
(s / 'absolute-link.txt').symlink_to(s / 'docs' / 'report.txt')
(s / 'directory-link').symlink_to('docs', target_is_directory=True)
(s / 'broken-link.txt').symlink_to('missing.txt')
os.mkfifo(s / 'example.pipe', 0o640)   # FIFO 管道：仅 macOS / Linux；Windows 没有这一项，请删掉这一行
os.chmod(s / 'docs' / 'report.txt', 0o640)
for name in ['archives', 'restored-full', 'restored-encrypted', 'restored-incremental']:
    (r / name).mkdir()
print('演示根目录：', r)
print('源目录：', s)
print('备份目录：', r / 'archives')
print('属主（Owners 筛选可填）：', (s / 'README').owner())
PY
```

这段准备脚本在 macOS 上运行。Windows 需要重新确认链接权限和文件系统能力，不能照搬已验证的结论，也没有 FIFO。

**FIFO 管道只许看、不许读：** 不要对 `example.pipe` 执行 `cat`、读取、哈希，或用编辑器打开它。管道没有写入端时，任何读取都会一直阻塞。软件本身也从不打开管道的数据流，只记录它的元数据。

## 3. 核对命令

先确认环境变量仍指向本次的临时目录：

```bash
diff "$PPT_DEMO_ROOT/source/docs/report.txt" "$PPT_DEMO_ROOT/restored-full/docs/report.txt"
ls -li "$PPT_DEMO_ROOT/restored-full/docs/report.txt" "$PPT_DEMO_ROOT/restored-full/docs/report-hard.txt"
readlink "$PPT_DEMO_ROOT/restored-full/relative-link.txt"
readlink "$PPT_DEMO_ROOT/restored-full/absolute-link.txt"
ls -l "$PPT_DEMO_ROOT/restored-full/broken-link.txt"
ls -l "$PPT_DEMO_ROOT/source/example.pipe" "$PPT_DEMO_ROOT/restored-full/example.pipe"
stat -f '%Sp %Su:%Sg  %N' "$PPT_DEMO_ROOT/source/relative-link.txt" "$PPT_DEMO_ROOT/restored-full/relative-link.txt"
```

最后一条是 macOS 的写法；Linux 用 `stat -c '%A %U:%G  %n'`。

怎么读结果：

- `diff` 没有输出，说明内容一致。
- `ls -li` 里两个文件的 inode 相同，说明硬链接关系还原了。
- 相对软链接还原后相对于**还原目录**解析；绝对软链接仍指向原来的绝对路径。两者不是同一种效果，不能说成一样。
- 断开的链接是刻意放的样本，不是还原故障。
- 管道：源和还原目录里的 `ls -l` 输出都以 `p` 开头，权限一致（准备脚本里是 `rw-r-----`）。**只看 `ls -l`，不要读它。**
- 软链接自身的权限 / 属主 / 属组：`stat` 输出在源和还原目录里应一致。属性匹配时软件不告警；macOS 上权限不同时用 `chmod -h` 恢复并核对，外部目标不受影响。
- 普通读文件操作可能更新访问时间，**检查时间要在读取内容之前进行**。

2. 对还原结果的实际核对；

| 顺序 | 删减内容 | 可省时间 |

## 7. 常见追问的回答口径

| 问题 | 准确回答 |
| --- | --- |
| 压缩 / 加密算法是自己写的吗？ | 归档组织和备份逻辑是自己实现的；压缩与密码算法使用 JDK 标准实现，不是自研密码算法。 |
| 为什么两个文件内容相同不一定是硬链接？ | 内容相同不能证明共享同一个文件系统对象，硬链接按文件身份识别。 |
| 为什么备份时不跟随软链接？ | 避免扩大扫描范围和递归循环，保留链接本身的含义。 |
| 为什么恢复成功还有警告？ | 数据已恢复，但部分属性受权限 / 平台限制，例如 FIFO 的创建时间无法恢复、时间只到整秒。软链接属性与清单一致时不告警，平台不支持或真正失败才告警。 |
| 软链接的权限、属主会恢复吗？ | 会先核对再恢复：与清单一致就不动；POSIX 属主 / 组用不跟随链接的设置器；macOS 上权限不同时用 `chmod -h` 恢复并再次核对，外部目标不受影响。不支持或失败才给出具体警告。 |
| 属主筛选怎么匹配？ | 按文件属主的用户名精确匹配、忽略大小写，多个用分号分隔；取不到属主信息的条目不匹配非空条件；不是按用户组筛选。 |
| FIFO 为什么不读内容？ | 管道没有可归档的字节内容，读取没有写入端的管道会一直阻塞。所以只记录它的元数据，还原时用 `mkfifo -m` 重建，用 `touch` 恢复时间。 |
| 那还算“只用 JDK 标准库”吗？ | 常规功能只用 JDK 标准库、没有第三方运行库；FIFO 恢复另调系统的 `mkfifo` / `touch`，只在 POSIX 环境可用，所以不能说成“完全没有外部依赖”。 |
| 设备文件和 socket 支持吗？ | 不支持，遇到会跳过并提示；FIFO 只在 POSIX 环境有条件支持。 |
| Windows 上能用吗？ | 常规备份、加密等可移植的功能按设计可运行，但只在 macOS 实机验证过；不支持的能力（FIFO、部分 POSIX 属性、链接）在测试里按能力跳过，没有 Windows 实机验证。 |
| 为什么第 11 次重新全量？ | 限制增量链长度，形成能够整组管理和淘汰的依赖单元。 |
| 为什么重启后不是继续增量？ | 新进程不复用无法确认配置与密码兼容性的旧基线，首次创建全量。 |
| 增量能单独还原吗？ | 通常不能，需先恢复全量及前序增量；界面逐份叠加，不自动串联。 |
| 源目录删除的文件会从还原目录消失吗？ | 不会；当前增量是叠加恢复，不做删除同步。要干净的快照，应全量恢复到空目录。 |
| 测试覆盖率多少？ | 已有 87 个用例全部通过，但未采集覆盖率，不报百分比。 |
| 支持网盘或多用户吗？ | 不支持。已按项目范围删除网络模块，专注本地备份。 |
