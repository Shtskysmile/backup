**3. 另开一个终端窗口，粘贴下面四行（zsh，已逐条验证）。** 它们只是少打字：`src` 把源目录放进剪贴板，`last` 把最新归档的完整路径放进剪贴板，`meta` 用于验证。


## 3. 演练中发现的坑

**已修复的两个界面问题（本次）：**

1. 勾选 Encrypt archive 时连续点 Back up to server，第二次也是全量。原因：界面每次点击都 `new NetworkBackupService()`，而加密口令的“记忆”存在服务实例里。现在整个窗口只建一个实例。
2. 默认窗口宽度下 Network 页的右侧被裁。原因：一行 FlowLayout 控件（1038 px）把整页撑到 1246 px，而页面的横向滚动条被禁用，多出的部分被静默裁掉。现在把连接区、备份参数区各拆成两行，整页 828 px，连最小窗口（850 px）也放得下。

两处都是先写失败的回归测试（`BackupFrameWindowTest`，2 项）、看到它因正确的原因失败，再改的代码。改动在 `BackupFrame.java`（另有 `BackupApplication.java` 里一处不改行为的提取），**已提交为 `e225375`**。

**仍然存在、演示时要知道的：**

1. **快照下拉默认选中最新一项（增量）**，还原整棵树要手动选 `full`。
2. **错口令的弹窗文字是底层的 `Tag mismatch`**，不是友好提示；口径：GCM 认证失败，说明口令错误或数据被篡改，目标目录不产生任何输出。
3. **状态徽标变琥珀色 `2 warnings`** 来自 FIFO 的属性提示，预期，不是失败。
4. **先启动定时再做别的事时，若弹出 “A backup or restore is running. Please wait for completion.”**，点 OK 再点一次（手动操作遇到自动任务正在执行会被拒绝；任务只持续毫秒级，很少遇到）。
5. 旧 JAR 没有 Network 页，也没有上面两处修复；`example.pipe` 不要读。
