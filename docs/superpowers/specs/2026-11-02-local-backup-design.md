# 本地备份功能补齐设计

日期：2026-11-02

状态：用户于 2026-11-02 确认，已按本设计实现；实施裁定与验收结果见同日期实施计划。

## 目的和范围

按课程评分表补齐本地功能：路径、类型、名字、时间、尺寸筛选；旧备份淘汰；软链接和硬链接；元数据恢复。保留现有 Java 21、Swing、ZIP/GZIP、密码加密、定时和实时备份。无需启动服务器。

后续用户要求已于同日落实：删除网络代码、上传配置及服务入口，产品仅保留本地备份功能。命名管道、设备文件、socket 文件不在本轮范围；遇到这些对象应报告跳过，不能尝试读取造成阻塞。因此特殊文件评分能覆盖软硬链接，但不承诺覆盖全部特殊文件。

## 方案比较

1. **补齐本地功能，扩展现有结构（用户选择）**：所有新增能力接入现有界面与服务。归档清单增加版本和条目类型；继续读取旧归档。改动涉及扫描、归档、恢复、自动化和界面，但符合本轮完整补齐的目标。
2. **先做筛选与淘汰**：变更小，能较快提供两个功能；链接与元数据仍留缺口。用户未选。

不更换技术栈，不新增数据库或外部常驻进程。

以下为已确认的规则；平台验证产生的必要裁定在对应段落和实施计划中记录。

## 1. 自定义筛选

备份页增加可展开的筛选区域；默认全部留空，等同当前的完整目录备份。

| 条件 | 规则 |
| --- | --- |
| 路径 | 相对于源目录的包含和排除 glob；多条以分号分隔；示例 `docs/**`；说明匹配分隔符统一为 `/` |
| 类型 | 按扩展名筛选，可填 `txt;pdf`，忽略扩展名大小写；无扩展名单独可选 |
| 名字 | 仅匹配文件名的 glob，如 `report*`，多条以分号分隔 |
| 时间 | 最早与最晚修改时间，包含边界；输入格式 `yyyy-MM-dd HH:mm:ss`，使用系统本地时区 |
| 尺寸 | 最小与最大字节数，包含边界；允许只填一端 |

不同条件之间取交集，同一条件多条取并集；路径排除规则优先。非法通配符、日期、负数、上下界颠倒在开始前提示，不产生归档。

筛选针对文件和链接，保留已选对象所需的祖先目录；默认无筛选时保留空目录。显式排除的目录不递归。类型、名字、时间、尺寸条件不应直接阻断目录遍历。

软链接按链接自身路径、名字、修改时间和链接记录大小匹配，不读取目标内容；界面说明。硬链接在筛选完成后选择已入选的一个路径保存实体数据，其余路径引用它，避免引用被筛掉的文件。

手动、定时、实时三种触发使用相同选项快照。

## 2. 软链接和硬链接

清单条目显式区分目录、普通文件、软链接和硬链接。

- 软链接保存原始目标字符串；支持相对、绝对和断开的链接；扫描不跟随软链接，也不扫描源目录外的目标。
- 硬链接依据文件系统身份识别；只保存一次内容。无法可靠识别时按普通文件备份并提示，不能仅凭内容哈希认定两个文件是硬链接。
- 恢复先写普通文件，再创建硬链接，最后创建软链接。硬链接目标必须是本快照中的合法普通文件，且实际内容已经恢复或由已还原的基线提供。
- 软链接可以保留指向恢复目录外的原始目标，但恢复过程绝不通过它读取、写入或设置外部目标的属性。
- 在写文件、建目录、建链接和回填属性前检查路径及父目录；遇到恢复目标中已有软链接父目录即拒绝该条目，防止写出目标目录。
- 普通文件目标本身已有软链接时也拒绝写入。普通文件先写同目录临时文件，再替换目标，避免原位截断意外改变另一个硬链接路径；正确处理普通文件与链接的类型切换。
- 若目标文件系统不支持链接或权限不足，明确报告失败，不把失败的链接计为成功恢复。

## 3. 元数据

继续保存修改时间、POSIX 权限、属主和组；增加访问时间。只在目标平台明确支持时尝试恢复创建时间；不承诺恢复 inode 变更时间、ACL、扩展属性和所有平台的原生属性。

采集时在读取文件内容之前记录属性，避免哈希计算改变访问时间后才记录。恢复内容及链接后再恢复属性，目录按从深到浅的顺序处理，防止创建子文件改变已回填的目录时间。

属主和组按名字查找；设置所有权后再设权限和时间。软链接时间使用不跟随链接的属性视图；不支持时跳过并记录原因。macOS 实测 JDK POSIX 权限设置即使指定不跟随仍可能影响外部目标。2026-11-05 修订为先核对链接自身属性：一致不告警；属主/组使用安全的不跟随设置器，macOS 不同权限使用 chmod -h 并验证；不支持或真正失败时告警。不会为恢复属性申请提权或运行 sudo。

恢复结果区分：数据恢复失败、数据成功但属性有警告、全部成功。日志记录具体路径和属性；界面展示警告数量。原来静默忽略属性异常的逻辑需要替换。

## 4. 定时备份和淘汰

自动化页增加“保留最近 N 组备份”，默认 `0`（关闭淘汰）；正整数启用。启用后适用于该组配置的手动、定时和实时备份。

一组备份是一份全量基线及其后续增量归档，整组保留或淘汰，不拆散依赖。N 表示备份组数，磁盘归档数量可能多于 N；界面明确说明。

每组最多包含 10 次成功快照（1 次全量及最多 9 次增量），之后新建全量，以避免增量链无限增长。每次全量备份开启新组。首次启用且无法确认历史依赖时，新建全量。

只有新归档、对应清单及最新索引成功写入后才执行清理。备份失败不清理旧数据。清理失败作为警告，不能把已成功写出的备份报告为完全失败。

仅管理能够由有效清单和归档配对确认、属于同一备份任务的文件；不按文件扩展名盲删目录内容。归档和旁挂清单成对清理，最新索引保留。清单声明的归档名不能越出备份目录。

任务身份由规范化源目录、用户备份名和筛选规则确定；不同身份不得共用增量基线或相互清理。筛选、源目录、备份名变化后开启新的全量链。加密状态、密码或归档类型变化后也开启新链；密码比较仅在应用内存中完成，不持久化密码或额外验证标记。应用每次启动后的首次备份创建新全量，避免跨进程猜测密码是否一致。

沿用现有的“先恢复全量基线，再按时间顺序手动应用增量”的恢复方式，界面和文档明确提示，并展示新归档的组标识及先后顺序。本轮不实现自动发现和串联整条恢复链。

若前次恢复产生的只读目录阻止后续手动增量应用，应明确报告对应路径及权限原因，由用户调整目标目录权限后重试；本轮不自动放宽已有目标目录权限，不静默跳过失败条目。

本轮增量恢复仍为叠加恢复：处理新增、内容变化、元数据变化和链接变化，不自动删除源目录已删除的旧文件。要获得不包含旧文件的当前完整状态，创建全量并恢复到空目录。筛选变化会开启新组。此限制必须在 README 和恢复界面说明，不对用户恢复目录执行删除同步。

## 5. 格式与兼容

新清单使用版本 2，增加条目类型、链接目标、额外时间、任务身份、快照 ID、父快照 ID 和组标识。读取版本 1 时按旧目录/普通文件模型处理，缺少的属性不强行补零。

ZIP 和 GZIP 均支持新条目，链接不存目标文件的内容。GZIP 新格式明确使用新的格式标识，避免新旧字节布局混读。现有版本 1 的 ZIP、GZIP、加密归档仍能恢复；旧程序无需支持新归档。

归档写入临时文件后再完成最终文件和索引发布，避免失败归档成为最新基线。修正同秒归档名称冲突时对候选清单名检查不一致的问题。

并发保护覆盖本应用单实例的备份和还原；自动触发忙时的更改不能永久丢失，应按任务身份各自合并成后续一次任务；停止自动化时取消对应待执行请求。恢复进行期间不执行备份淘汰。不承诺多个独立应用进程同时操作同一备份目录的协调能力。

## 6. 界面和文档

沿用现有 Swing 风格。备份页增加筛选区；自动化页增加保留设置和链依赖说明；还原页显示增量恢复顺序说明与元数据警告。此次不做整套界面重设计。

更新 README、需求分析和系统设计中与本轮行为直接相关的段落；增加可复现的本地验收步骤。网络能力说明不得写成此次新增成果。

## 7. 验证与交付

先为有意义的行为写失败测试，再实现；保留现有四个测试。新增验证包括：

- 五种筛选、组合和排除优先级；空目录、中文文件名、边界值与非法设置。
- 软链接相对/绝对/断开目标；硬链接身份；过滤后硬链接仍可恢复；不跟随外部链接。
- ZIP/GZIP、加密与链接组合；旧格式归档可读。
- 修改时间、访问时间、权限；目录时间；属性不支持或权限不足时有警告。
- 同秒连续备份、多任务共用目标目录、筛选变化、新增/修改及仅属性变化；验证删除文件不触发恢复目录删除同步的已声明行为。
- 保留策略不误删无关文件，整组保护增量依赖，10 次快照后新建全量，失败不触发清理。
- 恶意路径、已有软链接父目录，以及指向外部路径的软链接不导致外部写入。
- 目标文件自身为软链接时拒绝普通文件写入；硬链接拆分及类型切换不会改写另一条路径；手动增量遇只读目录时有明确错误。
- 定时、实时入口使用筛选和保留设置，忙时变化后续仍有备份。

在当前 macOS 文件系统运行链接和 POSIX 验证；不支持的平台测试应明确说明跳过原因。无 Maven 时使用现有本地 JUnit 依赖运行测试，产品编译仍以 Java 21 为目标。最后进行 Swing 界面检查并记录结果。

交付包含代码、测试、文档和验收结果；不启动服务器、不部署、不替用户启用定时任务，不对真实备份执行清理测试。
